# archive/lab

Сжатие и распаковка файлов без потерь. Собственный LZ77/Huffman, стандартный DEFLATE и автоматический выбор наименьшего архива. Формат — `.sarc`, проверка содержимого — SHA-256.

**Стек:** TypeScript, Node.js 22, Fastify, Vite, HTML/CSS.

## Запуск

Требуется Node.js 22 LTS версии 22.12 или новее с npm.

```sh
npm install
npm run dev
```

Интерфейс: [http://127.0.0.1:5173](http://127.0.0.1:5173). API: `http://127.0.0.1:3000`. Остановка — Ctrl+C.

Собранная версия, после остановки режима разработки:

```sh
npm run build
npm start
```

Интерфейс и API доступны на [http://127.0.0.1:3000](http://127.0.0.1:3000) из одного процесса. Адрес задаётся переменными `HOST` и `PORT`; по умолчанию — `0.0.0.0:3000`. Dev-прокси настроен на порт 3000.

Для отдельного production-каталога достаточно `dist/`, `package.json` и `package-lock.json`. Зависимости устанавливаются командой `npm ci --omit=dev`, запуск — `npm start`. Тесты, TypeScript и Vite для этого не нужны.

## Использование

Выбрать файл и метод на вкладке «Сжать», выполнить сжатие и скачать архив. Для восстановления загрузить архив во вкладке «Распаковать» и скачать исходный файл.

AUTO сравнивает LZ/Huffman, RLE, DEFLATE и хранение без сжатия. LZ/Huffman ищет повторяющиеся фрагменты, включая повторы на расстоянии более 32 KiB. Универсального преимущества над DEFLATE нет; AUTO выбирает меньший результат на конкретных данных.

## API

API приложения доступен без авторизации. Спецификация API организаторов не предоставлена.

| Запрос | Поля | Результат |
| --- | --- | --- |
| `GET /api/health` | — | JSON со статусом и версией |
| `POST /api/compress` | `file`, необязательное `method` | Бинарный архив `.sarc` |
| `POST /api/decompress` | `file` | Бинарный исходный файл |

POST-запросы используют `multipart/form-data`, принимается ровно один файл в поле `file`. Значения `method`: `auto` (по умолчанию), `lz`, `deflate`. Значение `rle` сохранено для совместимости. Формат архива проверяется по содержимому. Чтение старых архивов SARC v1 поддерживается; новые архивы записываются в v2.

Проверка сервера:

```sh
curl -fS http://127.0.0.1:3000/api/health
```

Ответ: `{"status":"ok","version":"1.0.0"}`.

Сжатие файла собственным алгоритмом:

```sh
curl -fS -F "file=@example.txt" -F "method=lz" http://127.0.0.1:3000/api/compress -o example.sarc
```

Распаковка:

```sh
curl -fS -F "file=@example.sarc" http://127.0.0.1:3000/api/decompress -o restored.txt
```

В PowerShell использовать `curl.exe`. Путь после `@` — загружаемый файл, `-o` — место сохранения ответа. Для просмотра заголовков добавить `-D -`.

Ответы с файлами имеют тип `application/octet-stream`. Имя передаётся в `Content-Disposition`. Заголовки `X-Original-Size`, `X-Archive-Size` и `X-Codec` содержат размеры в байтах и кодек: `STORE`, `RLE`, `LZ` или `DEFLATE`. После успешной распаковки возвращается `X-Checksum-Verified: sha256`.

Ошибки возвращаются в JSON:

```json
{"error":{"code":"CHECKSUM_MISMATCH","message":"Проверка SHA-256 не пройдена: архив повреждён."}}
```

Коды HTTP: `400` — неверные данные, `413` — превышение размера, `415` — неподдерживаемый формат, `404` — неизвестный маршрут, `503` — сервер занят или превышено время обработки, `500` — внутренняя ошибка.

## Ограничения

- Один файл до **100 MiB** (104857600 байт); загрузка архива до **102 MiB**.
- Обработка в памяти без сохранения файлов на сервере. БД не используется.
- Одна операция одновременно. Вычисления выполняются в worker thread; HTTP-сервер остаётся доступным. Обработка ограничена 120 секундами, прерывание запроса останавливает worker.
- Для предельных размеров рекомендуется 2 GiB свободной RAM.
- Архив может быть больше исходника. Длинные и опасные имена нормализуются.
- Один файл на архив; папки, ZIP-совместимость и пароли не поддерживаются.
