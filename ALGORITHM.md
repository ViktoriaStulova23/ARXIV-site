# Алгоритмы и формат SARC

## Ядро

`core/archive.ts` экспортирует независимые от HTTP функции:

```ts
compress(bytes: Buffer, filename: string, method: 'auto' | 'lz' | 'rle' | 'deflate' = 'auto')
// { bytes: Buffer, filename, codec, originalSize }

decompress(archiveBytes: Buffer)
// { bytes: Buffer, filename, codec, originalSize, verified: true }
```

## LZ77 / Huffman

Собственная реализация находится в `core/lz.ts` и `core/huffman.ts`. Готовые библиотеки сжатия в этом кодеке не используются.

LZ77 заменяет повторяющийся фрагмент парой «длина, расстояние». Поиск выполняется по хешу трёх байтов и цепочке предыдущих позиций. Проверяются до 48 кандидатов. Для коротких совпадений сравнивается также совпадение со следующей позиции. Максимальное расстояние — 1048575 байт, максимальная длина совпадения — 65537 байт.

Вход обрабатывается блоками до 1048576 байт. Словарь сохраняется между блоками. Для блока строятся два дерева Хаффмана: для литералов/длин и для расстояний. Частые символы получают более короткие коды. Длина кода ограничена 15 битами; при чрезмерно глубоком дереве используются равномерные коды активных символов. Это корректный, но менее эффективный запасной вариант.

Перед записью битового потока рассчитывается его точный размер. Если блок не уменьшается, он записывается без сжатия. Для работы переиспользуются словарь, массив токенов и буфер одного блока; несжатые блоки ссылаются на исходный буфер. Полные промежуточные копии для каждого блока не создаются.

LZ полезен для текста, структурированных данных, длинных повторов и повторяющихся фрагментов на расстояниях больше окна DEFLATE в 32 KiB. DEFLATE может сжимать другие данные лучше. Показатели зависят от содержимого.

### Полезная часть LZ

Блоки следуют друг за другом до конца payload. Все целые — little-endian.

| Смещение в блоке | Размер | Поле |
| --- | --- | --- |
| 0 | 4 | Восстановленный размер блока, от 1 до 1048576 |
| 4 | 4 | Размер сохранённых данных блока |
| 8 | 1 | Режим: 0 — исходные байты, 1 — LZ/Huffman |
| 9 | переменный | Данные блока |

Для режима 0 размеры обязаны совпадать. Для режима 1 данные начинаются с uint16 длины таблиц, затем идут таблицы, сжатые собственным RLE, и битовый поток. После декодирования таблицы содержат ровно 292 байта:

- 272 длины канонических кодов для литералов и длин;
- 20 длин канонических кодов расстояний.

Нулевая длина означает отсутствие символа. Коды назначаются по возрастанию длины, затем номера символа. Переполненные деревья и обращения к отсутствующим кодам отклоняются.

Биты записываются от старшего к младшему. Символы 0–255 обозначают исходные байты. Символ `256 + k`, где `k` от 0 до 15, обозначает длину `2 + 2^k + extra`, за кодом идут `k` бит `extra`. После длины записываются код расстояния `d` от 0 до 19 и `d` дополнительных бит: расстояние равно `2^d + extra`.

Количество восстановленных байтов определяется размером блока. Остаток последнего байта заполняется нулями. Лишние байты, ненулевое заполнение, усечения, выход за блок и ссылки до начала восстановленных данных отклоняются. Перекрывающиеся ссылки поддерживаются.

Пустой файл имеет пустой LZ payload. Худший размер несжимаемых данных — исходный размер плюс 9 байт на блок.

## RLE

Собственный RLE находится в `core/rle.ts`. Формат сохранён для совместимости с SARC v1 и используется также для таблиц LZ.

| Управляющий байт `c` | Значение | Следующие байты |
| --- | --- | --- |
| 0–127 | Литерал длиной `c + 1` | `c + 1` байтов |
| 128–255 | Повтор длиной `c - 128 + 3` | Один повторяемый байт |

Это вариант с подходом PackBits, но с другим кодированием блоков. Поддерживаются любые байты, длинные серии и пустой вход. Максимальная длина — `n + ceil(n / 128)`.

Размер рассчитывается отдельным проходом. В ручном режиме результат записывается сразу в итоговый архив; отдельного полного буфера-кандидата нет. Публичный `encodeRle` выделяет буфер точного размера. Декодер проверяет весь поток перед выделением результата.

## DEFLATE, STORE и AUTO

DEFLATE использует стандартный `node:zlib`: `deflateRawSync` с `level: 6`, `windowBits: 15`, `memLevel: 8`. Это библиотечный алгоритм. STORE сохраняет исходные байты.

AUTO сравнивает STORE, RLE, LZ и DEFLATE. Заголовки имеют одинаковую длину для одного имени. Замена происходит только при строго меньшем payload; при равенстве приоритет — STORE, RLE, LZ, DEFLATE.

Для RLE сначала вычисляется размер. LZ прекращает построение кандидата, если тот уже не может стать меньше текущего. DEFLATE ограничивается размером текущего лучшего кандидата: превышение лимита означает, что он не выиграет. Это сохраняет выбор минимального результата без хранения всех полных вариантов одновременно.

## Контейнер `.sarc`

Новые архивы записываются как SARC v2. Декодер принимает v1 и v2; кодек LZ разрешён только в v2. Старые номера кодеков и структура общего заголовка сохранены.

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 4 | Magic: ASCII `SARC` |
| 4 | 1 | Версия: 2; чтение версии 1 поддерживается |
| 5 | 1 | Кодек: 0 STORE, 1 RLE, 2 DEFLATE, 3 LZ |
| 6 | 4 | Исходный размер, uint32 LE, не более 104857600 |
| 10 | 2 | Длина имени `N`, uint16 LE, не более 255 |
| 12 | 32 | SHA-256 исходного содержимого |
| 44 | N | Имя в UTF-8 |
| 44 + N | до конца | Payload выбранного кодека |

Размер заголовка — `44 + N`. Длина имени задаётся в байтах. Некорректный UTF-8 отклоняется. Имя нормализуется в NFC и безопасный basename, управляющие и опасные символы удаляются, зарезервированные имена Windows защищаются. Обрезка выполняется по границам UTF-8-символов.

Перед распаковкой проверяются версия, кодек, заголовок и исходный размер. Затем проверяются длина результата и SHA-256 через `timingSafeEqual`. SHA-256 подтверждает целостность содержимого, но не подлинность архива; имя отдельно не защищено контрольной суммой.

## Ограничения и ресурсы

Исходный файл ограничен 100 MiB, архив — 102 MiB. Этот запас покрывает рост RLE, DEFLATE и заголовки LZ. RLE и LZ ограничивают выход объявленным размером; DEFLATE использует `maxOutputLength`. Хвост после потока DEFLATE отклоняется.

В API ядро выполняется в отдельном worker thread. Входные и выходные ArrayBuffer передаются с передачей владения. Только непередаваемые pooled-буферы Node копируются в отдельный буфер. После операции worker завершается, освобождая временную память. При обрыве запроса или превышении 120 секунд worker останавливается.

Память остаётся линейной: исходник, результат, словарь и рабочие блоки. Число одновременных операций ограничено одной. HTTP-сервер обслуживает health и возвращает 503 новым операциям во время обработки.

## Оценка размера

При исходном размере `O` и полном размере архива `A` коэффициент равен `A / O`, экономия — `(1 - A / O) × 100 %`. Заголовок учитывается. Для пустого файла процент не определяется, отображается увеличение в байтах.

AUTO не гарантирует уменьшение файла: даже STORE добавляет заголовок. Отдельные методы сравниваются на одинаковых байтах; преимущество на одном образце не означает преимущество на всех форматах.
