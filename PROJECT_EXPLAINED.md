# Описание проекта

Веб-приложение выполняет сжатие и распаковку файлов без потери данных. Архивы сохраняются в формате `.sarc`. После распаковки проверяются размер и SHA-256 восстановленного содержимого.

## Архитектура

Проект поделён на три части:

| Часть | Расположение | Назначение |
| --- | --- | --- |
| Интерфейс | `client/`, `index.html` | Выбор файла и метода, запросы, отображение результата и скачивание. |
| Сервер | `server/` | HTTP API, приём файлов, запуск worker и возврат результата. |
| Ядро архиватора | `core/` | Алгоритмы, формат архива и проверка целостности. |

Тяжёлые вычисления выполняются в отдельном worker thread. Основной поток продолжает обслуживать HTTP-запросы. Буферы передаются между потоками с передачей владения, без копирования содержимого. Если Node.js запрещает передачу буфера, предварительно создаётся отдельная копия. После завершения операции worker освобождается.

## Технологии

Клиент, сервер и алгоритмы написаны на TypeScript со строгой проверкой типов. Интерфейс использует HTML и CSS. Fastify принимает HTTP-запросы, `@fastify/multipart` — файлы, `@fastify/static` — отдаёт собранный интерфейс. Vite используется при разработке и сборке. Vitest используется для проверок и не нужен при production-запуске.

## Сжатие

Основной собственный алгоритм — LZ77 с каноническим кодированием Хаффмана. LZ77 заменяет повторяющиеся фрагменты ссылками на уже встречавшиеся данные. Хаффман сокращает запись часто используемых символов и ссылок.

Данные обрабатываются блоками до 1 MiB. Словарь сохраняется между блоками. Если сжатие блока не уменьшает его размер, блок хранится без сжатия. Код находится в `core/lz.ts` и `core/huffman.ts`.

RLE сохранён для серий одинаковых байтов и чтения старых архивов. Его размер сначала рассчитывается без создания полного промежуточного буфера. Для самого RLE выделяется ровно необходимая память.

DEFLATE используется из стандартного модуля `node:zlib`. Режим AUTO выбирает наименьший результат среди STORE, RLE, LZ и DEFLATE. Размеры сравниваются по фактическим данным. Превосходство одного метода на всех файлах не предполагается.

## Формат и восстановление

Заголовок SARC хранит версию, кодек, исходный размер, имя и SHA-256. Новые архивы используют версию 2; чтение версии 1 сохранено.

При распаковке проверяются структура блоков, границы ссылок, ограничения размеров и контрольная сумма. Повреждённые архивы отклоняются. Имя приводится к безопасному виду.

## API

- `GET /api/health` — состояние сервера.
- `POST /api/compress` — файл и метод сжатия, в ответе архив.
- `POST /api/decompress` — архив, в ответе восстановленный файл.

Браузер передаёт файл через `FormData` и `XMLHttpRequest`. Загрузка начинается после нажатия кнопки действия. Результат скачивается через временный object URL, который освобождается при замене или закрытии результата.

## Ограничения

Исходный файл — до 100 MiB, загружаемый архив — до 102 MiB. Файлы обрабатываются в памяти, без записи на диск. Одновременно выполняется одна операция. Прерывание запроса останавливает обработку.
